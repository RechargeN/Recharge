Статус: **Draft, 2026-11-24.** Независимого Security-заключения нет (D-06). Production — после него.

## Что защищает сейчас

| Слой | Состояние |
|---|---|
| Вход | Google → Firebase → серверная Session; отзыв «на всех устройствах» проверен на A34 |
| Допуск | Session — любой Google-аккаунт (L-16, нужно правило допуска до когорты); остальные модули — список разрешённых uid |

| Лимиты на пользователя | `security/abuse_policy.ts` (rate-limit команд); Discover — до 3 запросов в секунду; лимитов частоты публикаций нет (RATE-PUB) |
| Расходы | `maxInstances 1` у функций; бюджет только оповещает |
| Репозиторий | ruleset `protect-main-and-integration`, secret scanning + push protection |

## Сценарии

### Утечка ключа или секрета
`secret-leak-response.md`. Пример 2026-11-23/24: Maps-ключ из публичной истории — новый ключ с ограничением по пакету и SHA-1 и одному API, проверка на A34, старый удалён, alert закрыт как revoked.

### Всплеск запросов от одного пользователя
1. Журнал функции: uid и семейство (без содержимого).
2. Rate-limit отвечает отказом сам; если не хватает — убрать uid из списка разрешённых и выложить (2–3 мин).
3. Записать в журнал инцидентов.

### Всплеск запросов без входа (пробы, сканеры)
Отвечают 401 до работы приложения; расходы ограничены `maxInstances`. Если `*-slo-fast-burn` — проверить, не наши ли это пробы (так было 18.11).

### Вредный контент
Модерации в облаке нет (MOD-CLOUD). До неё: владелец снимает публикацию командой автора или выключает кодбазу публикации (`*_ENABLED=false`, 2–3 мин).

### Захват аккаунта
Пользователь или владелец: «Выйти на всех устройствах» (отзыв всех Session); при необходимости — блокировка аккаунта (данные с телефона не стираются, решение 2026-11-23).

### Расходы растут
`backend-cost-response.md` и раздел выключателей в `staging-monitoring-alerts-cost.md`. Отключение биллинга — только решением владельца.

## Чего нет до production

Принуждения App Check (Play Integrity для релизной сборки), Data Access audit logs, второго человека и break-glass, модерации и лимитов публикаций, правила допуска к входу.
