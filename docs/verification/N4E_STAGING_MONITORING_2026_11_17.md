## 4. Оповещения о сервисе — заведены 2026-11-17

Решение владельца 2026-11-17: «Да, заводи». Применено через Terraform (`bootstrap/stage/n4e_alerts.tf`): план проверен сторожем `check-n4e-plan`, 13 добавлено, 0 изменено, 0 удалено; IAM без стопов. Ресурсы прочитаны обратно из API.

| Ресурс | Что |
|---|---|
| Сервис `recharge-stage-functions` | 5 SLO по метрикам Cloud Run развёрнутых функций (без нагрузочного входа и задания по расписанию) |
| SLO доступности | вход, команды, чтение — 99,9 %; плохие ответы — 5xx и 429 |
| SLO задержки | команды — 95 % ≤ 1,5 с; чтение — 95 % ≤ 750 мс |
| `stage-slo-fast-burn` | сгорание ≥ 10× за 1 ч, выдержка 5 мин, 5 условий |
| `stage-slo-slow-burn` | сгорание ≥ 2× за 24 ч, выдержка 2 ч, 5 условий |
| `stage-probe-booking`, `stage-probe-session` | POST с недействительным токеном раз в 5 мин из 3 регионов, ожидается 401 |
| `stage-probe-failed` | проба не прошла больше чем в одном регионе 10 минут |
| `stage-server-errors` | в журнале Cloud Run ошибка или маркер `dev_*_failure` (ответ 503) |

Пробы работают: с 09:30 UTC обе проходят во всех трёх регионах (Бельгия, Вирджиния, Орегон) — функции отвечают 401 на недействительный токен.

Активная проверка: синтетический маркер `dev_n4e_probe_failure` записан в журнал staging 2026-11-17 09:28:45 UTC — ожидается письмо `stage-server-errors`. Сгорание и отказ пробы намеренно не вызывались: для этого пришлось бы ломать работающие функции.

Ограничения:
- Подтверждение «коротким окном» — выдержка условия, а не второе условие.
- Бизнес-отказы внутри ответа 200 (`retryableFailure`) в SLO не видны: SLO считают только HTTP-статусы.
- На почти нулевом трафике staging знаменатель дают пробы; единичная ошибка может дать быстрое сгорание.
- Пороги 50/75 % бюджета и «нет телеметрии» оповещениями не заведены.
- Стоимость: оповещения бесплатны до 2027-09-01; пробы — около 52 тыс. выполнений в месяц при 1 млн бесплатных.
