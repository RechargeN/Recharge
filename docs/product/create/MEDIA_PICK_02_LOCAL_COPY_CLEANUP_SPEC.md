# MEDIA-PICK-02 — локальные копии фото после серверной Media

Статус: **Approved** — владелец 2026-11-18 («Утверждаю OD-1–OD-5») с условиями
§2. Продолжение [MEDIA-PICK-01](MEDIA_PICK_01_IMAGE_SELECTION_SLICE_SPEC.md) §6,
поправка 1.

## 1. Цель

Локальная копия фото (JPEG без EXIF/GPS в приватной папке приложения) живёт,
пока она нужна для загрузки. Когда сервер подтвердил актив, поле черновика
ссылается на актив (`asset:<assetId>`), а копия удаляется.

## 2. Условия владельца (обязательны)

1. Удалять локальный файл только после подтверждения `ready` и успешного
   сохранения ссылки `asset:` в черновике.
2. Исключить потерю фотографий при сбоях, отсутствии сети и перезапуске.
3. При выходе из аккаунта сохранять незагруженные локальные черновики при
   строгой изоляции данных между аккаунтами.
4. В mock-режиме сохранять файлы, нужные опубликованным объектам.
5. Одинаковая логика для Android и iOS.

## 3. Решения OD-1–OD-5 (утверждены)

| # | Решение |
|---|---|
| OD-1 | Копия удаляется сразу после `ready`, привязки к серверному черновику и сохранения `asset:` в локальном черновике; публикации ждать не нужно |
| OD-2 | Удалять копии удалённого черновика и «сирот» при старте — см. §5.4 |
| OD-3 | При выходе из аккаунта незагруженные копии остаются; загруженных уже нет (OD-1) |
| OD-4 | Mock-режим: ничего не удаляется (нет `ready` — нет `asset:`) |
| OD-5 | iOS: та же логика; проверка — вместе с остальным iOS |

## 4. Как это устроено

1. **Ready.** Загрузчик Media возвращает id актива только при исходе `ready`
   (`MediaEventCoverUploader`); отказ и недоступность — ошибка, копия остаётся.
2. **Привязка.** Контроллер публикации (Place, Activity, Class / Workshop,
   Collection / Guide, Rental, Session) после загрузки сохраняет тело
   серверного черновика с этими активами и только тогда отдаёт пары
   «локальная копия → asset id» (`takeReadyMediaRefs`, читается один раз).
3. **Замена в форме.** Панель публикации передаёт пары форме
   (`CreateController.promoteReadyMedia`). Форма заменяет значения обложки и
   галереи на `asset:<id>`, переносит описания фото (`galleryAltText`) на новые
   ссылки и сохраняет черновик. Не сохранилось — ничего не заменено и не
   удалено.
4. **Удаление.** Только после успешного сохранения: копия, на которую не
   ссылается ни одно поле, заносится в журнал удалений
   (`create_media/released.jsonl`) и удаляется. Прерванное удаление
   завершается при следующей загрузке черновика того же аккаунта; копия, на
   которую черновик снова ссылается, остаётся.
5. **Повторная загрузка не нужна.** Поле `asset:` контроллеры публикации
   связывают без чтения файла и без загрузки (все шесть типов, а также
   локальный импорт, обложки маршрута и сценария).
6. **Изоляция аккаунтов.** Новые копии лежат в
   `create_media/<папка аккаунта>/<черновик>/`; папка — хэш id аккаунта, сам id
   в путях не встречается. Журнал удалений обрабатывается только для своего
   аккаунта; чужие записи и копии не трогаются. Черновики и так хранятся
   раздельно по владельцу.
7. **Mock-режим.** Без сервера нет `ready` и нет `asset:`, поэтому ни одна
   копия не попадает в журнал удалений и не удаляется; опубликованные
   mock-объекты сохраняют свои файлы.
8. **Платформы.** Вся логика — общий Dart-код без платформенных веток.

## 5. Отличия от черновика спецификации (2026-11-18)

1. **Превью.** Вместо серверной картинки форма показывает значок и надпись
   «Фото загружено на сервер» (`createMediaUploadedToServer`, en/ru/lv):
   у приватного актива черновика нет адреса для показа в клиенте.
2. **Обложки маршрута и сценария, Event** пока не переводятся на `asset:`
   (у них свой путь загрузки обложки); поле `asset:` они уже понимают.
3. Старые копии в прежней папке без аккаунта (`create_media/<черновик>/`) не
   удаляются автоматически: их владелец не определён, а потеря запрещена
   условием 2. Они удаляются по OD-1, если загружаются заново.
4. **Удаление черновика (OD-2)** в приложении сейчас нет; хук очистки
   появится вместе с этой функцией.
