# PVR-01 — готовые задания для передачи агентам

Дата: 2026-10-10. Подготовка заданий выполнена; сами заходы ещё не выполнены.

Пользовательский результат: один личный профиль Creator, прежние личные и
Creator-возможности, отдельные Professional Pages; Viewer как отдельная
страница/preview удаляется, его наработки сохраняются в архиве.

## Как использовать

1. Начни с файла 00. Отправь его целиком выбранному агенту: приложи Markdown
   или скопируй текст. Каждый файл содержит контекст, входы, задачи, точные
   пути, ограничения, проверки и требования к передаче результата.
2. Дальше передавай следующий файл по порядку. Это могут быть разные агенты,
   но они должны видеть одну подтверждённую целевую копию и результаты
   предыдущих заходов. Общий master plan — справочник, а не замена задания.
3. Завершивший агент пишет отдельный отчёт в `docs/verification/pvr-01/`
   целевой копии и добавляет ссылку в `docs/verification/PVR_01_VERIFICATION.md`.
   Следующий агент читает этот отчёт и сверяет реальные файлы.
4. Если агенты работают в разных checkout, сначала явно перенеси нужную
   дельту и отчёты с сохранением WIP. Одинаковый Git HEAD не гарантирует
   одинаковое uncommitted содержимое. Каждый следующий агент проверяет вход.
5. Не запускай эти задания параллельно над общей копией: profile, access,
   документы и отчёты имеют последовательные зависимости. Никаких агентских
   задач или сообщений из этого пакета автоматически не отправлялось.

## Решение после захода 02

Подготовленный Proposed ADR не равен Accepted. Если конкретный текст ещё не
принят пользователем, агент 02 отдаёт готовый ADR для одного предметного
согласования. После принятия он либо следующий агент фиксирует основание
и статус; дальнейшие обычные действия в согласованном объёме повторного
разрешения на каждый файл не требуют. Сам факт пересылки пакета заданий
не должен изображаться как уже состоявшееся принятие ещё не написанного ADR.

Основание: приоритет Accepted ADR и правило 9 `AGENTS.md` о согласовании
крупного файлового плана. Продуктовая цель — убрать отдельный Viewer — уже
выбрана; её не нужно обсуждать заново. Большие Draft профильные решения
не становятся Accepted вследствие этого небольшого изменения.

## Что обязательно остаётся в каждой передаче

- Фактический target root, HEAD/branch и relevant WIP на входе/выходе.
- Изменённые файлы, важные итоговые hashes, boundaries и собственная дельта.
- Actual ADR path/status и основание принятия, если применимо.
- Команды с cwd, exit codes, результаты тестов и критерии, которые подтверждены.
- Путь архива, сохранность snapshots, неизвестное/невыполненное и конкретный rollback.
- RESULT: ready / not_ready / needs_user_decision. Следующий заход сам не начинается.

Timeout/not-run/failure не записываются как pass. Статус Ready включает
готовность выходных артефактов для следующего агента, а не обещание завершить
их позже. Тесты local/mock не подтверждают device/cloud readiness.
