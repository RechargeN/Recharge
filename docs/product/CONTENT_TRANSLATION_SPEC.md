# Машинный перевод контента по запросу: этап 1

- Версия: **0.4 (поправка 1 ADR 0022: режимы перевода реализованы)**
- Дата: **2026-11-01**
- Статус: **Approved slice этапа 1** (ADR 0022 `Accepted`, решение владельца 2026-11-01)
- Граница: только local/Emulator, выключено по умолчанию, mock-адаптер; без сети,
  ключей и расходов
- Родитель: `docs/adr/0022-on-demand-machine-translation-of-public-content.md`

## 1. Результат

Читатель нажимает «Перевести» в Details и получает перевод названия, краткого и
полного описания на язык интерфейса. Оригинал остаётся на месте. На этапе 1 текст
«перевода» создаёт mock (`[lv→ru] текст`), поэтому качество перевода здесь не
проверяется и не может быть подтверждено тестами.

## 2. Контракт

Схемы: `packages/api_contracts/schema/content_translation/v1/`.

| Callable | Что делает | Расход |
|---|---|---|
| `offerContentTranslationV1` | Отвечает, показывать ли кнопку, или отдаёт готовый постоянный перевод | Нет |
| `translateContentV1` | Возвращает перевод из кэша или от адаптера | Только при промахе кэша |

`offerContentTranslationV1` дополняет поток ADR: клиенту нужно знать про флаг и язык
источника, а Catalog по инварианту 1 менять нельзя.

Запрос у обоих один: `schemaVersion`, `requestId`, `contentId`,
`publishedRevisionId`, `targetLocale`. Лишнее поле, в том числе текст, отклоняется
как `request_invalid`.

Отказы: `unauthenticated`, `request_invalid`, `translation_disabled`,
`same_language`, `unsupported_locale`, `source_unavailable`, `revision_changed`,
`quota_exceeded`, `budget_exhausted`, `provider_unavailable`. Все они есть в каталоге
сообщений L4 на трёх языках; соответствие проверяет контрактный тест.

## 3. Модуль `modules/content_translation`

Порядок в одной транзакции допуска: Session → флаг и L2 switch → язык → публичная
ревизия, T&S hold, allowlist → кэш → живой lease (ожидание без списания) → квота →
бюджет → lease. Затем вне транзакции: редакция контактов → адаптер → проверка ответа.
Завершающая транзакция сверяет token lease и повторно проверяет источник, затем
записывает кэш, ledger и бюджет.

| Коллекция | Содержит | Текст | Пользователь |
|---|---|---|---|
| `contentTranslations` | Записи кэша | Перевод | Нет |
| `contentTranslationLeases` | Lease на ключ и резерв | Нет | Нет |
| `contentTranslationAccountUsage` | Дневной счётчик аккаунта | Нет | `accountId` |
| `contentTranslationObjectUsage` | Дневной счётчик объекта | Нет | Нет |
| `contentTranslationBudgets` | Резерв и расход за месяц | Нет | Нет |
| `contentTranslationCostLedger` | Символы, сумма в minor units, валюта | Нет | Нет |

Все коллекции закрыты rules. Модуль читает Content и не пишет в него.

Удаление записей кэша: скрытие и удаление объекта (`syncContentTranslationsV1`),
T&S hold (`purgeContentTranslationsOnHoldV1`), истечение срока и пропущенный trigger
(`sweepContentTranslationsV1`, раз в сутки). Новая ревизия старые записи не
переписывает: они перестают совпадать и уходят по сроку.

## 4. Значения этапа 1

Это заглушки в коде, а не решения: TR-OD-04, 05 и 08 остаются открытыми.

| Параметр | Значение |
|---|---|
| Квота аккаунта | 20 промахов кэша в день |
| Лимит объекта | 10 промахов кэша в день |
| Месячный лимит | 100 minor units EUR |
| Срок кэша | 30 дней |
| Срок счётчиков | 2 дня |
| Ставка mock | 1000 minor units за 1 млн символов |
| Lease | 30 с; ожидание до 5 с |

После сбоя провайдера резерв бюджета возвращается, а квота остаётся потраченной: это
ограничивает повторные запросы.

## 5. Клиент

`ContentTranslationPanel` стоит между hero и телом Details. Она спрашивает
`offer`; при любом отказе не занимает места. Перевод показывается в отдельном блоке с
пометкой «Переведено автоматически», а не подменяет исходный текст: так не меняются
восемь рендереров и не теряется оригинал. «Показать оригинал» сворачивает блок,
повторное открытие не обращается к серверу. Перевод хранится только в памяти экрана.

Готовый постоянный перевод (`ContentTranslationReady`) панель показывает сразу, с
той же пометкой; «Показать оригинал» сворачивает его, повторное открытие сервер не
вызывает.

Включение: `--dart-define=RECHARGE_TEST_CONTENT_TRANSLATION=true`, режим `testBackend`,
loopback Emulator, не release. На сервере — флаг `contentTranslation.onDemand`, для
перевода при публикации ещё `contentTranslation.atPublication`.

## 6. Что не закрыто этапом 1

| ID | Ограничение | Что нужно |
|---|---|---|
| TR-G01 | `contentLocale` у Event, Activity, Rental, Collection необязателен: автор выбирает язык в форме без предвыбора. Старые ревизии и черновики без выбора получают `source_unavailable`, кнопки у них нет | Решение, делать ли выбор обязательным |
| TR-G02 | Кнопка есть в `DiscoverDetailsPage` (Place, Activity, Route) и `EventDetailsPage`, где есть `revisionRef`. Экраны Session, Class/Workshop, Rental, Collection читают локальные проекции без id ревизии, Scenario не имеет такого экрана | Id ревизии в этих проекциях |
| TR-G03 | Перевод показан блоком, а не на месте исходного текста | Решение после проверки на устройстве |
| TR-G04 | Жалоба из вида с переводом идёт на исходный объект штатно; модератору перевод не показывается | Этап 3 |
| TR-G05 | Числа квот, лимит и срок — заглушки | TR-OD-04, 05, 08 на этапе 2 |
| TR-G06 | Заключения Legal/Privacy и подтверждённых условий провайдера нет | TR-OD-01, 07 |
| TR-G07 | Строки lv и ru не проверены носителем | Общая проверка L4 |

Поэтому кнопка появляется для Place и Route, а для Event и Activity — если автор
выбрал язык. Rental и Collection уже публикуют язык, но экрана с id ревизии у них нет.

## 7. Приёмка

| № | Проверка ADR | Тест |
|---|---|---|
| 1 | Текст в запросе отклоняется | unit, contract, Emulator |
| 2 | Приватное поле не уходит в адаптер | Emulator (шпион), unit allowlist |
| 3 | Скрытие, ограничение, удаление: отказ из кэша и удаление записей | Emulator с реальными trigger |
| 4 | Новая ревизия не отдаёт старый перевод | Emulator |
| 5 | Конкурентные запросы дают один вызов; потерянный worker не пишет | Emulator |
| 6 | Квота, бюджет и kill switch до вызова | Emulator |
| 7 | Сбой провайдера оставляет оригинал и не кэшируется | Emulator, widget |
| 8 | Текст не попадает в логи, ledger и счётчики; L3 не используется | Emulator |
| 9 | Токены контактов восстанавливаются | unit, Emulator |
| 10 | DSR и legal hold покрывают счётчик; реестры L1 и L2 | L1-T-W22, L1-T-REG, L2-T-REG |
| 11 | Find People и условия отклоняются; положительный контроль | unit, Emulator |
| 12 | Content не меняется | Emulator |
| 13 | UI на трёх языках, 360 dp, шрифт ×2 | widget |
| 14 | Реальный клиент через Session | Emulator + Flutter (`RECHARGE_G_MOBILE=1`) |

Зелёные тесты подтверждают поведение механизма, а не качество переводов.

## 8. Поправка 1: режимы перевода (2026-11-02)

Решение владельца TR-OD-10, реализовано в том же объёме этапа 1 (local/Emulator,
mock-адаптер, выключено).

| Режим | Типы | Как работает |
|---|---|---|
| Постоянный | Place, Route, Activity, Collection, Rental | Перевод при публикации на остальные языки рынка, хранится без TTL, Details показывает его сразу |
| По запросу | Event, Session, Class/Workshop, Scenario | Кнопка «Перевести», кэш с TTL |
| Не переводится | Find People | Нет в allowlist |

Режим задан в `contentTranslationModes` рядом с allowlist; unit-тест сверяет, что у
каждого типа allowlist ровно один режим.

| Часть | Реализация |
|---|---|
| Включение | Флаг `contentTranslation.atPublication` поверх `contentTranslation.onDemand` и того же incident switch |
| Запуск | `syncContentTranslationsV1` на изменение pointer публикации: скрытый или удалённый объект теряет переводы, видимый постоянного типа переводится (`translateAtPublication`) |
| Сверка | `sweepContentTranslationsV1` раз в сутки: очистка, затем `reconcilePublications` по видимым публикациям |
| Квоты | Квоты читателя не применяются; ограничивает общий месячный лимит |
| Хранение | Записи `contentTranslations` с `persistent: true` и `expiresAtUtc: null` |
| Новая ревизия | Тот же текст — перевод переносится без вызова (`carriedFromRevisionId`); другой текст — новый вызов; записи прежних ревизий удаляются, пропущенные убирает sweep |
| Чтение | `offerContentTranslationV1` возвращает готовый перевод (`kind: translated`) только для постоянного типа; кэш перевода по запросу кнопку не заменяет |
| Отказ | Сбой, лимит или выключатель не мешают публикации; Details показывает кнопку |
| Удаление | Как у кэша: снятие, ограничение, удаление, L1 |

Тесты: Emulator — перевод при публикации и показ без вызова, перенос на ревизию с тем
же текстом, новый вызов при другом тексте и удаление прежних записей, сбой и лимит
без влияния на публикацию, kill switch, реальный trigger, сверка после пропуска,
удаление при скрытии; mobile — готовый перевод виден сразу с пометкой и
«Показать оригинал».

Открыто: переводы в поиске, правка перевода автором, ручной перевод собственного
контента Recharge, правило для длинных событий.

## 9. Откат

Выключить флаг или включить switch `contentTranslation.onDemand.incidentDisable`:
кнопка исчезает при следующем открытии Details, новые вызовы прекращаются. Полный
откат: удалить модуль, callable, trigger, панель и коллекции; Content, Catalog и
Booking от них не зависят.
