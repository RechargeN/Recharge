## Current Domain Clarification

As of 2026-07-20, Route, Scenario and Quick Plan are three separate product
concepts. Route is a publishable continuous track with anchors, segments, GPX,
elevation and POI on the line. Scenario is a standalone personal/public
city/day/weekend/trip plan made from independent stops and logistics. Quick
Plan is a lightweight personal/invited utility outside Create Hub and catalog.
Only an explicit one-way Expand action may create a new independent Scenario
from selected Quick Plan stops; there is no live link.

Historical P10–P60 entries retain the terminology used by the implementation
at that time. Labels such as `scenario route`, `Publish route` and route
handoff in those entries describe legacy runtime behavior, not the current
Route contract. Runtime renaming and migration are separate cleanup work after
stabilization. The canonical creation spec is
`docs/product/ROUTE_BUILDER_SPEC.md` v3.2. Platform gates are defined in
`docs/architecture/PLATFORM_FOUNDATION_SPEC.md` v2.1, and staged execution in
`docs/product/ROUTE_IMPLEMENTATION_ROADMAP.md` v1.0.

As of 2026-07-30, account, workspace and publisher are separate identity
concepts. Viewer and Creator share one `Personal profile` workspace and the
same consumer bottom navigation; verified Creator state and grants add tools
without a manual Viewer/Creator switch. Users switch only between the personal
workspace and exact Professional Pages they actively manage. A page workspace
uses `Page / Content / Create / Notifications / Account`. Admin tools are a
separate capability-gated surface and never a workspace or publisher.

Historical profile entries retain the `User / Creator / Pro generator`
terminology of their stabilization UI. That local tier switch and the
capability-derived `Pro generator` projection are migration debt, not the
current target contract. Canonical behavior is defined by
`docs/product/IDENTITY_PUBLISHER_SLICE_SPEC.md` v1.3. No production
identity/workspace runtime implementation is claimed by this clarification.

Accepted ADR 0016 and ADR 0017 now permit bounded local/mock
IDP-03A/04A/05A work during stabilization, including user-created local pages,
ownership quota 3, pending moderator requests, local notifications and
presentation-only Admin experience preview. They do not permit Firebase,
production auth migration, real verification decisions, authoritative quota
approval, backend grants or production ManagedPage publication.
The canonical implementation contract is
`docs/product/IDENTITY_PUBLISHER_SLICE_SPEC.md` v1.3.
