## Update Rules

1. Before implementation of any task, map it to one (or more) stage IDs from the table.
2. While implementing, move status to `In progress`.
3. After PR is open and checks pass, move to `Review`.
4. Move to `Done` only when DoD is satisfied and required gates are green.
5. Any architecture deviation must follow `docs/architecture/CHANGE_POLICY.md`.
6. Keep each row short: status, date, what the slice delivers (1–2 sentences),
   what is still open before `Done`, and a spec link — about 600 characters at
   most.
7. Do not record test counts, gate output, commands, pass-by-pass history,
   reverts or who found what here. That belongs in commit messages, PRs and
   slice specs. This file has no execution log.
